# Proxmox VE Suite v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the verbatim v1 copy in this repo into v2: cluster, node and optional guest resources by role, an active/standby cluster role, node modules on their own nodes, a cluster health score, and an Enhanced Script NetScan that creates and maintains it all.

**Architecture:** Every module stays a Groovy body with the shared preamble `scripts/lib/pve_common.groovy` prepended by `build/build.py`. The preamble gains the v2 mechanics (token property, failover, the role check, node scoping, the guest loop, the health score, the NetScan plan) as pure closures the harness drives against the mock API; Collector-only code (snippets, TopologySource, ERI PropertySources, the NetScan body) stays a thin layer. Module definitions are renamed to v2 names with `git mv`, so each change reads as a diff against v1.

**Tech Stack:** Groovy 4 / JDK 17 (the Collector's runtime, run in `groovy:4-jdk17` Docker), Python 3 build, the `logicmonitor-modules` skill's lint and dashboard checks.

**Spec:** `docs/superpowers/specs/2026-10-21-proxmox-v2-architecture-design.md` (cited as **A§n**) and `docs/superpowers/specs/2026-10-25-netscan-design.md` (cited as **N§n**). Read both; this plan argues from them and does not repeat their reasons.

## Global Constraints

- Every script starts `//!/lib-groovy/v4` (the preamble's first line); Groovy 4, JDK 17.
- Token property: **`pve.token.credential`**; never read or write `pve.api.token.credential` anywhere (A§3.5).
- Categories: `ProxmoxVE_Cluster` (cluster resource), `ProxmoxVE_Node` (node), both on a standalone host, `ProxmoxVE_Guest` (guest). Never `ProxmoxVE` (v1's). Categories mark what a resource is, never something that changes (A§3.1).
- Role property: `pve.cluster.role` ∈ `active` | `standby` | `none`; `pve.cluster.active` = active node name, `address:<host>`, or `none` (N§5.1).
- AppliesTo, exactly:
  - cluster modules: `pve.cluster.role == "active" || pve.cluster.role == "standby"`
  - node API modules: `hasCategory("ProxmoxVE_Node") && pve.netscan.reachable != "false"`
  - `Proxmox_VE_Info`: `hasCategory("ProxmoxVE_Cluster") || hasCategory("ProxmoxVE_Node")`
  - `addERI_Proxmox_VE_Node`: `hasCategory("ProxmoxVE_Node")`
  - `addERI_Proxmox_VE_GuestResource`: `pve.guest.mac || ((auto.network.mac_address =~ "^[bB][cC]:24:11" || pve.guest.mac_prefix) && (isLinux() || isWindows()))`
- Module names (A§3.2 table), one per v1 module: `Proxmox_VE_Cluster_Status`, `_Cluster_Nodes`, `_Cluster_GuestStatus`, `_Cluster_GuestPerformance`, `_Cluster_StorageCapacity`, `_Cluster_Ceph`, `_Cluster_CephOSD`, `_Cluster_Backups`, `_Cluster_Snapshots`, `_Cluster_Topology`, `_Node_Detail`, `_Node_Disks`, `_Node_Services`, `_Node_Certificates`, `_Node_Subscription`, `_Node_Replication`, `Proxmox_VE_Info`, `addERI_Proxmox_VE_Node`, `addERI_Proxmox_VE_GuestResource`. Display names: `Proxmox VE ` + the words after `Proxmox_VE_`, split on `_` and camel case (e.g. `Proxmox VE Cluster Guest Status`).
- Guest instance wildvalues stay `pveWildValue(id)` (`qemu-101`); never embed a node (A§3.2).
- Exit 0 on success; non-zero with a reason on `System.err` on failure; never zero-fill; every printed value numeric; BatchScript keys `##WILDVALUE##.`; `deleteInactiveInstances`/`autoDeleteInstances` false (skill rules; v1 build enforces most).
- A cluster module on a resource that should not collect prints **nothing** and returns **0** (A§3.1).
- NetScan: emits every property every run with explicit values (`ok`, `none`), only the static groups `<root>/Cluster - <cluster>`, `…/Nodes`, `…/Guests`, `<root>/Host - <node>`; guests only with LM API credentials; never sends a changed hostname (N§3, §4, §6).
- `technicalNotes` and script comments state current behaviour only; dates, spikes and history belong in the specs (skill suite-design §9).
- Verification each task: `python build/build.py`, `docker compose -f tests/docker-compose.yml run --rm compile`, `docker compose -f tests/docker-compose.yml run --rm tests` → `PASSED  all N checks`.

## Review Focus

1. **A standalone host** (`/cluster/status` has no `cluster` row): role `active`, no standby, health score counts it quorate, the NetScan writes one resource with both categories and `Host - <node>`. Tests: Task 4 (`role-standalone`), Task 8 (`health-standalone`), Task 12 (`ns-standalone`).
2. **The role pair's lowest node ID is offline at the first NetScan run**: it is still `active`, the next node is `standby` and collects. Tests: Task 4 (`role-standby-takeover`), Task 12 (`ns-pair-offline`).
3. **IPv6 node addresses** (`fd00::12` in the fixture) in `pve.api.hosts`, node hostnames and the owner-node URL: bracketed in URLs, never mangled. Tests: Task 3 (`hosturl-ipv6`), Task 9 (`guestloop-ipv6`).
4. **A rejected token (401/403)** must not fail over to the next address (it is wrong everywhere) and must exit 2 at once, naming the token. Test: Task 3 (`failover-401`).
5. **No pressure fields** (PVE 8, or an empty `rrddata`): the node score falls back to load ÷ cores and never prints a fabricated score. Tests: Task 6 (`detail-no-pressure`), Task 8 (`health-fallback`).
